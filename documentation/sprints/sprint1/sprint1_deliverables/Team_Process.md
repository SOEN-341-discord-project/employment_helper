# Team Process Definition

## Workflow
We use the GitHub project board to organize our tasks and keep track of what needs to be done. Each team member works on their assigned tasks and updates the team on their progress.

## Branching Strategy
When working on a feature, team members can create their own branch so they do not affect the main version of the project. Once the feature is working, it can be merged into the main branch.

## Pull Request Process
When changes are ready, a pull request is created before merging into the main branch. This allows other team members to see the changes before they are added.

## Code Review Process
Other team members can review and test the changes. If there are problems, we discuss them and make the necessary changes before merging.

## Definition of Ready
A task is ready when:
- We understand what needs to be done.
- The task is clear
- Someone is assigned to work on it.

## Definition of Done
A task is done when:
- The feature is working
- It has been tested.
- Any major problems are fixed.
- The changes are added to the main branch
